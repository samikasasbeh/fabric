# Reviewed trigger files

One file per app, named `<appId>.json`, in the trigger format of `docs/F10.9-BUILD-MAP.md` section 8, with the two changes of `docs/I07-BUILD-MAP.md` section 2.6. `loadActionCatalog()` in `lib/action-catalog.mjs` reads every `*.json` here beside the app's action file, refuses a file not named after its `appId`, and validates each with `validateTriggerFile()`. A bad file refuses that app's triggers and never its actions. A trigger is active only when its file is reviewed, it is certified, every step places, every transform it names still has its pinned code, and its record in `docs/live-evidence/<appId>/triggers.json` passes: one test saw exactly one event after a write and none on the re-poll, and a trigger on a `history-id@1` cursor also resynced with one gap and no duplicate (I8). Anything less stays a candidate, which no agent is offered. The loader ignores this README, and git keeps the folder because of it.
